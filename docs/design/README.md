# dropgate 설계 (정본)

한정판 드롭 플랫폼. 기술 실험용 B2C 개인 프로젝트. 2026-10-06 착수, 7주 + 버퍼 1주 + 운영 비서 2주. 플랜과 측정 계획은 `docs/plan.md`.

방식: 슬라이스가 아니라 설계 선행. 이 폴더의 설계를 먼저 확정하고 주차 계획대로 구현한다. 설계를 바꾸려면 코드가 아니라 여기를 먼저 고치고 레포 docs/adr에 이유를 남긴다. 이 폴더가 정본이다.

| 파일 | 내용 |
|---|---|
| 00-설계-개요.md | 방식, 사용자 기능, 서비스 경계, 모듈 구조, 기술 결정 요약, 전체 흐름 |
| 01-ERD.md | PostgreSQL 스키마 셋(auth, orders, settlement), 컬럼, 제약, 트리거, 인덱스, 합성 데이터 |
| 02-Redis-키-설계.md | 키 목록, TTL, 대기열과 입장, 구매와 보상 Lua 계약, 전체 장애 정책, Streams, Sentinel |
| 03-DynamoDB-설계.md | 알림 테이블 키와 속성, 조건부 쓰기 멱등, 커서 조회, JSONB 비교 측정 |
| 04-이벤트-명세.md | Streams 메시지 필드, payload v1, 생산과 소비 규칙, DLQ |
| 05-API-명세.md, openapi.yaml | 엔드포인트 19개, 공통 규칙, 오류 코드 18개, 계약 테스트 |
| 06-배치-설계.md | 결산 잡과 대조 잡, 스텝과 청크, 재시작, CronJob, 측정 |
| 07-쿠버네티스-배포-설계.md | 워크로드, 프로브와 종료, Ingress, Secret, HPA 실측, Terraform 모듈, CD |
| 08-시퀀스-흐름.md | 로그인, 대기열에서 구매, 확정에서 알림, 취소와 보상, 배치, 장애 시나리오 |

구현 순서는 docs/plan.md의 주차 계획과 같다. 1주 차는 이 설계 중 auth 스키마, drops와 orders와 order_ledger, DB만 경로, 인증 엔드포인트 6개, 드롭과 주문 엔드포인트 중 대기열 제외 6개를 만든다.

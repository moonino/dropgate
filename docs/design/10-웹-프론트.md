# 10 웹 프론트

사용자 흐름을 사람이 눌러 보고 보여 주기 위한 웹 화면이다. 플랜 1절의 측정 대상 기술이 아니므로 백엔드 규칙을 새로 만들지 않고, 정해진 API를 화면으로 잇기만 한다. 구조 결정은 ADR 0020.

## 1. 위치와 스택

| 항목 | 결정 |
|---|---|
| 위치 | 같은 레포 `web/`. Gradle 멀티모듈 밖의 npm 프로젝트 |
| 프레임워크 | Next.js 16 App Router, React 19, TypeScript |
| API 타입 | `docs/design/openapi.yaml`에서 openapi-typescript로 만든다. 생성물은 커밋하고 PR 줄 수에서 뺀다. CI가 다시 만들어 차이가 있으면 실패한다 |
| 테스트 | Vitest와 Testing Library로 화면과 컴포넌트, MSW로 백엔드 응답 모의 |
| 포트 | 3000 |

## 2. BFF 구조

```
브라우저 -> web(Next.js 서버, 3000) -> auth-service 8081
                                    -> order-service 8082
                                    -> notification-service 8083 (4주 차)
```

- 브라우저는 web 출처하고만 통신한다. CORS를 열지 않는다.
- 백엔드 호출은 서버 컴포넌트와 서버 액션, 라우트 핸들러에서만 한다. 호출은 `web/src/server/backend` 래퍼 한곳을 거친다. 래퍼는 쿠키의 액세스 토큰을 Bearer로 붙이고, 응답의 `{code, message, errors}`를 그대로 화면에 넘긴다.
- 화면은 code로 분기하고 message는 그대로 보여 준다(05 공통 규칙). 재고, 1인 1회, 취소 가능 여부를 web이 따로 판단하지 않는다.

## 3. 세션 쿠키

| 쿠키 | 값 | 속성 | 수명 |
|---|---|---|---|
| `dropgate_access` | 액세스 토큰 | httpOnly, Secure, SameSite=Lax, Path=/ | TokenPair.expiresIn(900초) |
| `dropgate_refresh` | 리프레시 토큰 | httpOnly, Secure, SameSite=Lax, Path=/session | 14일. 2주 차 재발급 중계에서 쓴다 |

- 화면에 보이는 닉네임과 역할은 액세스 토큰 쿠키가 있을 때만 요청마다 `GET /auth/me`로 받는다. 토큰을 디코딩해 화면에 쓰지 않는다.
- 인증이 필요한 화면이나 호출에서 액세스 토큰이 없거나 백엔드가 401 UNAUTHENTICATED를 주면 두 쿠키를 지우고 로그인 화면으로 보낸다. 공개 화면은 토큰이 없거나 401이면 비로그인으로 보여 준다. 재발급 중계를 붙이기 전까지는 15분이 지나면 다시 로그인한다.
- 503 AUTH_UNAVAILABLE이면 쿠키를 지우지 않고 Retry-After 초만큼 뒤에 다시 시도하라고 보여 준다.

`/session` 아래는 web의 세션 라우트(로그아웃, 재발급 중계)다. 재발급 중계의 흐름은 2주 차 리프레시 백엔드와 함께 이 절에 더한다(ADR 0020).

## 4. 로그인 흐름 (08 1절과 같은 흐름에 web이 끼어든다)

1. 브라우저 GET web `/auth/login/kakao`. web 라우트 핸들러가 auth-service `GET /auth/login/kakao`를 리다이렉트를 따라가지 않고 부르고, 받은 302의 Location과 state 쿠키(Set-Cookie)를 그대로 브라우저에 돌려준다
2. 카카오가 web `/auth/callback/kakao?code&state`로 돌아온다. Redirect URI는 `http://localhost:3000/auth/callback/kakao`(ADR 0020)
3. web 라우트 핸들러가 code, state, 브라우저가 보낸 state 쿠키를 auth-service `GET /auth/callback/kakao`에 그대로 넘긴다
4. 200 TokenPair면 세션 쿠키 둘을 쓰고 auth-service가 보낸 state 쿠키 삭제 헤더를 함께 돌려준 뒤 `/drops`로 302. 400, 502, 503이면 로그인 화면으로 보내 code별 문구를 보여 준다

state 쿠키는 auth-service가 Path=/auth로 만들고, 브라우저 입장에서 출처가 web 하나라 web의 `/auth/callback/kakao` 요청에 실린다. auth-service는 바뀌지 않는다.

## 5. 화면

| 경로 | 화면 | 인증 | 쓰는 API | 주차 |
|---|---|---|---|---|
| `/login` | 로그인 | 없음 | web `/auth/login/kakao` | 2 |
| `/drops` | 드롭 목록, 더 보기 | 없음 | GET /api/drops | 2 |
| `/drops/{dropId}` | 드롭 상세, 오픈까지 카운트다운, 구매 | 구매만 | GET /api/drops/{dropId}, POST /api/drops/{dropId}/orders | 2 |
| `/orders` | 내 주문, 더 보기, 취소 | 필요 | GET /api/orders/me, POST /api/orders/{orderId}/cancel | 2 |
| `/admin/drops/new` | 드롭 등록 | ADMIN | POST /api/admin/drops | 2 |
| `/drops/{dropId}/queue` | 대기열 순번, 예상 대기, 입장 타이머, 포기 | 필요 | POST /api/drops/{dropId}/queue, GET /api/drops/{dropId}/queue/me, DELETE /api/drops/{dropId}/queue/me | 3 |
| `/notifications` | 알림 피드 | 필요 | GET /api/notifications/me | 4 |

- 화면은 그 API가 나온 주나 그 뒤에 붙인다. 웹 트랙은 2주 차에 시작하므로 1주 차 API 화면은 2주 차다. 백엔드보다 먼저 만들 때는 MSW 모의로 개발하고 테스트한다.
- 남은 수량은 null이면 숫자 대신 "집계 전"으로 보여 준다(1주 차 ADR 0005).
- 카운트다운은 서버가 준 openAt과 브라우저 시각으로 계산한다. 화면 표시용일 뿐이고, 열렸는지는 서버 상태가 정한다. 0이 되면 상세를 다시 불러 상태를 확인한다.
- 대기열 폴링은 2초(08 2절).

## 6. 오류 표시

| code | 화면 동작 |
|---|---|
| UNAUTHENTICATED | 인증이 필요한 화면이나 호출이면 세션 쿠키 삭제, 로그인 화면으로. 공개 화면이면 비로그인으로 표시(3절) |
| FORBIDDEN | 관리자 화면이면 권한 안내, 취소면 message 표시 |
| VALIDATION_FAILED | errors의 field마다 해당 입력란 아래에 message |
| DROP_NOT_OPEN, SOLD_OUT, ALREADY_PURCHASED, NOT_ADMITTED | 구매 버튼을 해당 상태로 바꾸고 message 표시 |
| ORDER_ALREADY_CANCELED, DROP_CLOSED | 주문 행의 취소 버튼을 비활성화하고 message 표시 |
| DROP_NOT_FOUND, ORDER_NOT_FOUND | 찾을 수 없음 화면 |
| 503 전부 | message와 Retry-After 초 뒤 다시 시도 안내. 자동 재시도는 대기열 폴링만 |

## 7. 시각 디자인

방향 이름은 게이트 보드다. 출발 안내판처럼 숫자가 주인공인 다크 화면이다. 고른 이유는 셋이다. Drop 스키마에 이미지가 없어 사진 카드보다 숫자와 글자 중심 보드가 데이터와 맞는다. 보여 줄 것이 재고, 순번, 입장 타이머 같은 실시간 수치다. 강조색 하나로 "지금 행동할 수 있음"만 표시하면 드롭 상태 넷과 대기 상태 셋이 색, 모양, 문구로 겹치지 않게 갈린다. 조사 근거(Nike SNKRS, KREAM, 무신사, Queue-it, Cloudflare Waiting Room, Linear, Vercel의 실측과 문서)는 이슈 #90에 남긴다.

### 색 토큰

색은 CSS 변수 토큰으로만 쓴다. 나중에 라이트 토큰을 더할 수 있게 화면 코드에 hex를 직접 쓰지 않는다. 대비는 WCAG 상대 휘도 공식으로 계산한 값이다.

| 토큰 | 값 | 쓰임 | 대비 |
|---|---|---|---|
| `--color-bg` | #0B0B0D | 배경 | |
| `--color-surface` | #17171A | 칸과 카드 | |
| `--color-line` | #2A2A2F | 장식 구분선 | |
| `--color-border` | #6B6B73 | 의미 있는 테두리, 입력란 | 배경 위 3.72:1 |
| `--color-text` | #F2F2EE | 본문 | 배경 위 17.5:1 |
| `--color-text-muted` | #9A9AA2 | 보조 글자 | 배경 위 7.0:1, 표면 위 6.4:1 |
| `--color-text-disabled` | #85858E | 비활성 버튼 글자 | 표면 위 4.89:1 |
| `--color-accent` | #C8F23C | OPEN 구매, ADMITTED 입장, 확정 | 배경 위 15.2:1, 위에 쓰는 글자는 `--color-bg` |
| `--color-danger` | #FF6B5E | 오류, 취소 버튼 | 배경 위 7.0:1 |
| `--color-warning` | #FFB547 | 입장 마지막 10초 | 배경 위 11.2:1 |

### 글꼴

- 본문과 제목: Asta Sans(Google Fonts, 가변 300에서 800). 본문 400 이상 16px 이상, 제목 700에 자간 -0.02em. 다크에서 얇은 한글이 뭉개지므로 400 미만은 쓰지 않는다.
- 숫자, 시각, 순번, 코드: Geist Mono. 숫자가 바뀌어도 폭이 흔들리지 않게 `font-variant-numeric: tabular-nums`도 같이 둔다.
- 한국어 조판은 `lang="ko"`와 `word-break: keep-all`.

### 상태 표현

색만으로 상태를 나누지 않는다. 배지는 늘 문구와 모양을 같이 바꾼다.

| 상태 | 문구 | 모양 |
|---|---|---|
| SCHEDULED | 오픈 예정 | `--color-border` 외곽선 알약 |
| OPEN | 판매 중 | `--color-accent` 채움, 어두운 글자 |
| SOLD_OUT | 품절 | `--color-line` 채움, 보조 글자 |
| CLOSED | 마감 | 점선 외곽선, 보조 글자 |
| 주문 CONFIRMED | 확정 | 강조색 외곽선 |
| 주문 CANCELED | 취소됨 | 점선 외곽선, 보조 글자 |

### 화면 구성

- 드롭 목록은 사진 카드가 아니라 행 보드다. 열은 오픈 시각, 드롭, 수량, 상태, 보기. 좁은 화면에서는 한 행이 여러 줄로 접힌다.
- 드롭 상세는 칸 넷이다. 맨 위 전체 폭 칸에 카운트다운과 구매 버튼, 아래에 남은 수량, 일정, 규칙.
- 카운트다운은 칸으로 나눈 시, 분, 초(Geist Mono 80px 안팎) 바로 아래에 절대 시각("10월 18일 (일) 19:30 오픈")을 함께 둔다. OPEN이면 마감까지를 센다.
- 구매 버튼 문구는 서버 상태를 따른다. 오픈 전 "19:30 오픈"(비활성), OPEN "구매하기"(강조), 오류 code를 받으면 "품절", "이미 구매함", "입장 필요"로 바꾸고 서버 message를 버튼 아래에 둔다.
- 대기열은 화면 하나에 큰 숫자 "내 앞 N명"(10,000을 넘으면 "10,000명 이상"), 진행 바(들어올 때 순번 기준), 예상 대기, 마지막 갱신, 고정 문구 "새로고침하지 않아도 자동으로 갱신됩니다". 입장하면 화면이 강조색 판으로 바뀌고 남은 초를 큰 숫자와 줄어드는 바로 보여 준다. 마지막 10초는 경고색. 만료되면 다시 줄 서기.
- 최대 폭 1200px, 칸 모서리 20px, 버튼은 알약 모양, 터치 영역 44px 이상. 글래스와 3D는 쓰지 않는다.

### 접근성

- 보이는 타이머는 `role="timer"`라 매초 읽히지 않는다. 숨긴 `role="status"` 영역에 10분, 1분, 10초 전과 "판매가 열렸습니다"만 한 번씩 알린다.
- 입장 허가와 입장 만료는 `role="alert"`로 한 번만 알린다. 입장 60초 규칙은 대기열에 들어가기 전에 미리 보여 준다(WCAG 2.2.1의 필수 시간 제한으로 본다).
- 대기 순번은 2초 폴링마다 읽지 않고 30초 간격이나 큰 변화 때만 status로 알린다.
- 숫자 전환은 150ms 페이드만, `prefers-reduced-motion`이면 끈다.

## 8. 모의 모드

`DROPGATE_WEB_MOCK=true`면 web 서버의 백엔드 호출을 MSW 핸들러가 받는다. 카카오 키와 백엔드 없이 화면을 띄워 볼 수 있다. 로그인은 모의 사용자(USER 하나, ADMIN 하나)를 고르는 화면으로 대신한다. 테스트도 같은 핸들러를 쓴다. 운영 빌드에서는 켜지지 않게 프로덕션 모드에서 이 값을 무시한다.

## 10. 배포

6주 차 kind 배포에 web Deployment 하나와 Service를 더하고 Ingress의 `/`를 web으로 보낸다. 백엔드 서비스는 클러스터 안에서만 web이 부른다. 07 문서는 6주 차에 고친다.

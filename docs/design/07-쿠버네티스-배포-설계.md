# 07 쿠버네티스 배포 설계

차트 하나 `deploy/helm/dropgate`, values 파일 둘(kind, eks). 네임스페이스 `dropgate`.

## 워크로드

| 이름 | 종류 | 복제 | 자원 요청 / 상한 | 비고 |
|---|---|---|---|---|
| auth | Deployment | 2 | 250m 512Mi / 1 CPU 1Gi | |
| order | Deployment + HPA | 최소 2 최대 6 | 500m 768Mi / 1 CPU 1.5Gi | CPU 60% 기준. 릴레이와 입장 스케줄러 포함 |
| notification | Deployment | 2 | 250m 512Mi / 1 CPU 1Gi | Streams 소비자, 파드 호스트명이 소비자 이름 |
| settlement | Deployment | 1 | 500m 1Gi / 1 CPU 2Gi | 배치 서버. 복제 1(JobLauncher 중복 실행 방지) |
| settlement-daily | CronJob | | 50m 64Mi | curl 이미지, 15:10 UTC, concurrencyPolicy Forbid, backoffLimit 2 |
| reconciliation-hourly | CronJob | | 50m 64Mi | 매시 05분 |
| redis | Bitnami redis 차트, sentinel.enabled | 복제 3(마스터 1 복제 2), 센티넬 3 | kind만 | EKS는 ElastiCache |
| dynamodb-local | Deployment | 1 | kind만 | EKS는 DynamoDB |

PostgreSQL은 kind에서는 클러스터 밖 로컬 컨테이너(호스트 네트워크), EKS에서는 RDS.

## 프로브와 종료

| 항목 | 값 | 이유 |
|---|---|---|
| readiness | GET /actuator/health/readiness, 초기 10초, 주기 5초, 실패 3회 | DB와 Redis 연결 포함. Redis가 죽어도 order는 ready 유지(조회 API는 살아 있어야 함). 대신 Redis 상태는 별 지표 |
| liveness | GET /actuator/health/liveness, 초기 20초, 주기 10초, 실패 3회 | 앱 자체만 |
| 종료 유예 | terminationGracePeriodSeconds 40, preStop sleep 5, Spring graceful shutdown 30초 | 롤링 배포 중 진행 중 요청 완료. 값 근거는 ADR 0014에 실측 |
| 롤링 | maxSurge 1, maxUnavailable 0 | 부하 중 배포 오류 0 목표 |
| PDB | minAvailable 1 (order는 2) | 노드 drain 중 가용성 |

## 네트워크

Ingress(nginx, kind) 또는 ALB Ingress Controller(EKS). 경로:

| 경로 | 서비스 |
|---|---|
| /auth/*, /.well-known/jwks.json | auth:8081 |
| /api/drops/*, /api/orders/* | order:8082 |
| /api/notifications/* | notification:8083 |
| /batch/* | settlement:8084, 클러스터 안에서만(Ingress 노출 안 함, NetworkPolicy로 CronJob만 허용) |

## 설정과 비밀

ConfigMap: DB 호스트, Redis Sentinel 주소와 마스터 이름, DynamoDB 엔드포인트, 입장 스케줄러 주기. Secret: DB 비밀번호(서비스별 사용자), 카카오 client id와 secret, JWT RS256 개인키 PEM(auth만), AWS는 IRSA라 키 없음. kind에서는 Secret을 직접 만들고, EKS에서는 Terraform이 Secrets Manager에 넣고 External Secrets Operator로 끌어온다(시간이 없으면 kubectl create secret로 축소).

## HPA 실측 설계

k6 스파이크 0에서 1,000 요청/초 30초를 두 번 돌린다. 한 번은 대기열 끄고(입장 키를 항상 통과시키는 플래그), 한 번은 켜고. 기록: p99, 확장된 파드 수, 첫 확장까지 초, 5xx 수. HPA 안정화 창 기본값(확장 0초, 축소 300초)을 그대로 두고 측정 뒤 바꿀지 ADR에.

## Terraform (7주 차)

| 모듈 | 자원 |
|---|---|
| network | VPC, 퍼블릭 서브넷 2, 프라이빗 서브넷 2(2 AZ), NAT 1 |
| eks | 클러스터, 관리형 노드 그룹 t3.medium 3, IRSA, ALB Ingress Controller, metrics-server |
| data | RDS PostgreSQL 16 db.t4g.micro Single-AZ(연습 비용), ElastiCache 복제 그룹 cache.t4g.micro 2노드 Multi-AZ 자동 장애 조치, DynamoDB 온디맨드 + TTL |
| registry | ECR 리포지토리 4개 |
| observability | kube-prometheus-stack은 Helm으로, Grafana 대시보드 JSON은 레포에 |

GitHub Actions CD: main 머지 -> 테스트 -> 이미지 4개 빌드와 ECR push -> helm upgrade --install with values-eks.yaml -> 스모크(헬스 200). 실패 시 helm rollback.

## 측정 대상 정리

| 실험 | 어디서 | 기록 |
|---|---|---|
| 파드 3개 정확도 | kind, EKS | 초과 0, 중복 0 |
| 롤링 배포 10회 | kind, EKS | 5xx 수, 연결 거절 수 |
| 파드 강제 종료 | kind | 회복 초 |
| Redis 마스터 종료 | kind(Sentinel), EKS(수동 장애 조치) | 절체 초, 503 수, 대조 차 |
| 알림 파드 종료 | kind | pending 0까지 초, 건수 유지 |
| CronJob | kind | 정시 실행, 실패 재시도 |
| HPA 스파이크 | EKS | p99, 파드 수, 첫 확장 초 |
| 노드 drain | EKS | 프로브 실패 분 |

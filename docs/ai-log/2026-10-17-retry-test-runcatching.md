# 실패 뒤 다시 받는 테스트의 첫 호출 단언을 runCatching으로 버리지 않는다

| 항목 | 내용 |
|---|---|
| 날짜, 도구 | 2026-10-17, Claude Code 자동 리뷰 제안 |
| 제안 요지 | `조회가 실패한 뒤에 온 요청은 JWKS를 다시 받는다` 테스트가 첫 호출의 실패까지 단언해 바로 위 테스트의 개념을 겹쳐 검사하므로, 첫 호출은 `runCatching`으로 결과를 버리고 다시 받는지만 단언한다. |
| 왜 틀렸나 | 테스트 불일치. 첫 호출의 AUTH_UNAVAILABLE 단언은 다른 개념을 다시 보는 것이 아니라 테스트 이름의 전제(조회가 실패한 뒤)를 고정한다. `runCatching`으로 버리면 첫 호출이 실패하지 않아도 두 번째 호출이 키를 돌려주기만 하면 통과하므로, 테스트가 실패 뒤에 다시 받는지를 검증하지 않게 된다. |
| 어떻게 알았나 | 문서 대조. [리뷰 제안](https://github.com/moonino/dropgate/pull/65#issuecomment-6230578074) 3번을 feat/6-jwks-cache의 `JwkSetCacheTest.kt`와 대조했다. 첫 호출 단언을 버리면 남는 단언은 두 번째 호출이 `test-key`를 돌려주는지 하나뿐이고, 첫 호출이 실패했는지는 어디서도 확인하지 않는다. 같은 제안이 다음 차례 [리뷰 제안](https://github.com/moonino/dropgate/pull/65#issuecomment-6233188126) 2번에 다시 왔지만 테스트는 바꾸지 않았다. 테스트를 고쳐 실행해 보지는 않았다. |
| 대신 한 것 | 첫 호출을 `assertAuthUnavailable`로 단언하는 테스트를 그대로 두고, 기각 이유를 커밋 `refactor: 리뷰 지적을 반영한다 (#6)` 본문과 PR 본문에 적었다. PR #65 |

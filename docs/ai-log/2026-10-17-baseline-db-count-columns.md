# 기준선 측정 기록의 첫 결과 표에서 초과, 중복 열을 빼지 않는다

| 항목 | 내용 |
|---|---|
| 날짜, 도구 | 2026-10-17, Claude Code 자동 리뷰 제안 |
| 제안 요지 | `docs/measurements/2026-10-17-db-only-baseline.md` 첫 결과 표에서 DB에서 센 `초과`, `중복` 열을 빼고 같은 값은 DB 대조 표의 `oversold`, `duplicated_users`에만 둔다. |
| 왜 틀렸나 | 설계 불일치. 두 값이 k6 응답이 아니라 측정 뒤 DB에서 센 값이라는 지적은 맞고, 문서도 응답별 표 아래에서 그렇게 밝힌다. 그러나 DB 대조 표는 일곱 실행을 같은 결과 한 줄로 적으므로 실행마다 초과 0, 중복 0이 보이는 곳은 첫 표의 두 열뿐이다. plan.md 2절은 이 질문의 합격 기준을 초과 0, 중복 0으로 두고 ADR 0005는 측정으로 확인할 것을 초과 수, 중복 수, p99로 정하므로, 열을 빼면 기록이 설계가 요구하는 실행별 판정 근거를 잃는다. 어긋나는 대상은 docs/design/이 아니라 plan.md 2절과 ADR 0005이고, 원인 표에 이 경우에 꼭 맞는 항목이 없어 가장 가까운 설계 불일치로 적는다. |
| 어떻게 알았나 | 설계 문서 대조. [리뷰 제안](https://github.com/moonino/dropgate/pull/89#issuecomment-6230590842) 1번을 docs/plan.md 2절 표의 합격 열(초과 0, 중복 0)과 ADR 0005의 측정으로 확인할 것 항목(초과 수, 중복 수, p99)에 대조했고, 측정 문서의 DB 대조 표가 일곱 실행 모두 같은 결과라는 한 줄뿐임을 확인했다. |
| 대신 한 것 | 첫 표의 초과, 중복 열과 DB에서 센 값이라는 설명 문장을 그대로 두고, 같은 리뷰의 2번 제안(UNIQUE 방어 문장의 주어와 결론)만 커밋 `docs: 리뷰 제안을 반영한다 (#10)`로 반영했다. PR #89 |

# 신규 로그인 저장과 리프레시 회전을 구별한다

| 항목 | 내용 |
|---|---|
| 날짜, 도구 | 2026-10-19, Claude Code 자동 리뷰 제안(요약 댓글의 제안) |
| 제안 요지 | 토큰 발급과 Redis 저장을 서비스 메서드 하나로 옮겨 컨트롤러의 책임을 줄인다. |
| 왜 틀렸나 | 과잉. 콜백 전용 서비스로 옮기는 제안은 가능하지만 현재 두 호출을 위한 새 계층을 추가하지 않았다. 회전은 신규 로그인 저장을 재사용하지 않고 옛 키 소비와 새 키 저장을 원자로 처리하는 별도 서비스가 맡는다. |
| 어떻게 알았나 | 설계 문서 대조. docs/design/08의 신규 저장과 회전 계약을 과 대조했다. 제안 자체가 오류라는 뜻은 아니며 현재 범위에서 경계를 유지했다. [리뷰 제안](https://github.com/moonino/dropgate/pull/124#issuecomment-6260214384). |
| 대신 한 것 | 신규 로그인은 발급 뒤 저장하고, 재발급은 별도 서비스에서 회전 스크립트로 처리한다. PR #124와 #126. |

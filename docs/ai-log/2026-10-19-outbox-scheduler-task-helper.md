# 스케줄 등록 테스트의 짧은 탐색을 유지한다

| 항목 | 내용 |
|---|---|
| 날짜, 도구 | 2026-10-19, Claude Code 자동 리뷰 제안(요약 댓글의 제안) |
| 제안 요지 | 두 테스트의 ScheduledTaskHolder 조회와 릴레이 작업 선택을 relayTasks(context) 함수로 모은다. |
| 왜 틀렸나 | 과잉. 추출은 가능한 정리지만 등록 테스트는 작업의 fixed delay를 읽고 비활성화 테스트는 이름으로 부재를 확인한다. 짧은 준비 코드를 공통화해도 독립 활성화 계약의 검증 범위는 달라지지 않아 이번 범위에서 미룬다. |
| 어떻게 알았나 | 문서 대조. [후속 리뷰](https://github.com/moonino/dropgate/pull/145#issuecomment-6261405017)를 7f9fc67의 두 테스트와 비교했다. 등록 테스트는 FixedDelayTask의 간격, 미등록 테스트는 runnable 이름의 부재를 각각 확인한다. |
| 대신 한 것 | 중복 크기 단언과 다른 스케줄러의 부재 단언은 제거하고 짧은 준비 코드는 유지했다. PR #145. |

# 구매 Lua의 확정된 반환 계약을 유지한다

| 항목 | 내용 |
|---|---|
| 날짜, 도구 | 2026-10-19, Claude Code 자동 리뷰 제안(요약 댓글의 제안) |
| 제안 요지 | 구매 Lua가 숫자와 문자열을 함께 반환하는 대신 성공 수량 또는 거절 문자열 하나만 반환한다. |
| 왜 틀렸나 | 설계 불일치. 02 문서는 성공과 음수 코드 및 문자열 사유를 담는 반환 목록을 정본 계약으로 정했다. 구현 단계의 단순화 제안만으로 스크립트와 래퍼의 계약을 함께 바꿀 이유가 없다. |
| 어떻게 알았나 | 설계 문서 대조. [리뷰 제안](https://github.com/moonino/dropgate/pull/134#issuecomment-6260888510)을 02 문서의 purchase.lua 계약과 DropStockRepository에 대조했다. 래퍼는 숫자와 문자열을 StockReservation으로 변환하며 문자열을 서비스에 노출하지 않는다. 실제 Redis의 거절 순서와 동시성 검증이 통과했다. |
| 대신 한 것 | 반환 계약과 타입 경계를 유지하고 ARGV 입력에 이름을 붙이는 작은 명확화만 채택했다. PR #134 |

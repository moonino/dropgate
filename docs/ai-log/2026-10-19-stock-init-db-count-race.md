# 진행 중 주문을 놓치는 DB 건수 기반 자동 재초기화는 쓰지 않는다

| 항목 | 내용 |
|---|---|
| 날짜, 도구 | 2026-10-19, Claude Code 자동 리뷰 지적(인라인) |
| 제안 요지 | 초기 stock을 total_quantity에서 CONFIRMED 주문 수를 뺀 값으로 하고 buyers를 DB에서 채운다 |
| 왜 틀렸나 | 동시성 가정 오류. 판매 중 자동 복원에 DB 집계만 쓰면 Lua 차감 뒤 DB 커밋 전인 주문이 빠져 복원 재고와 나중에 확정되는 주문을 함께 판매할 수 있다 |
| 어떻게 알았나 | 설계 문서 대조. 08의 구매는 Lua 뒤 별도 DB 트랜잭션이므로 아직 확정되지 않은 예약은 CONFIRMED 집계에 없다. 독립 검토에서 이 경계를 대조했다 |
| 대신 한 것 | 재초기화 위험 지적은 반영하되 DB에 1회 초기화 권한을 영속 저장해 자동 복원을 막는다. 모든 주문 인스턴스와 DB 트랜잭션, Redis 연결과 미처리 쓰기를 제거한 뒤에만 DB 기준 수동 복원을 허용한다. PR #120 |

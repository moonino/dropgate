# 대조 결과를 출력하는 기존 단계 이름을 유지한다

| 항목 | 내용 |
|---|---|
| 날짜, 도구 | 2026-10-19, Claude Code 자동 리뷰 제안(요약 댓글의 제안) |
| 제안 요지 | print_accuracy_report가 완료 판정과 기록에서 읽을 파일도 만드니 write_reconciliation처럼 이름을 바꾼다. |
| 왜 틀렸나 | 과잉. 파일 생성을 드러내는 이름도 가능한 개선이지만 기존 함수는 화면에 대조 결과를 출력하면서 원본 JSON을 보존하는 경계다. 현재 호출자는 출력과 파일을 모두 사용한다. 선행 PR에서 병합한 실행 단계의 명명 변경을 완료 기록 기능에 섞을 필요가 없어 기존 이름을 유지한다. |
| 어떻게 알았나 | 문서 대조. [리뷰 제안](https://github.com/moonino/dropgate/pull/160#issuecomment-6263081205)을 head 5938ecc의 print_accuracy_report, main 및 완료 기록과 대조했다. 함수 안의 tee가 JSON 파일을 만들고 다음 판정이 그 파일을 읽는다는 설명은 맞다. 이번 판단은 명명 범위에 관한 것이며 새 실행이나 테스트를 수행하지 않았다. 해당 리뷰 검토 당시 실제 1만 요청 부하는 0회였다. |
| 대신 한 것 | 기존 출력과 보존 함수 이름을 유지한다. 같은 리뷰의 필수 중복 검증 제거와 판정 실패 시 파일 경로 안내는 반영한다. PR #160. |

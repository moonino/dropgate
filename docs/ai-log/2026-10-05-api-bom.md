# api 의존성의 버전 해석 실패 주장을 재현으로 확인한다

| 항목 | 내용 |
|---|---|
| 날짜, 도구 | 2026-10-05, Claude Code 자동 리뷰 |
| 제안 요지 | common에 버전 없는 api 의존성을 넣으면 실패하므로 BOM을 api로 옮긴다. |
| 왜 틀렸나 | 과잉. compileClasspath는 api 의존성과 implementation의 BOM 제약을 함께 사용한다. 외부 소비자에게 BOM을 노출할 필요와 현재 모듈의 의존성 해석은 별개다. |
| 어떻게 알았나 | [리뷰 2번](https://github.com/moonino/dropgate/pull/37#issuecomment-5994390614)을 아래 명령으로 재현했다. Boot BOM 제약으로 spring-core 7.0.9가 해석됐다. 성능 측정이나 합성 부하 시험은 아니다. |
| 대신 한 것 | implementation의 BOM을 유지한다. 외부 라이브러리 배포 시 api 공개 여부를 별도로 검토한다. PR #37 |

```sh
mkdir -p work
cat > work/api-bom.gradle <<'EOF'
gradle.beforeProject { p ->
    if (p.name == 'common') p.afterEvaluate {
        p.dependencies.add('api', 'org.springframework:spring-core')
    }
}
EOF
./gradlew :common:dependencyInsight --configuration compileClasspath --dependency spring-core --no-configuration-cache --init-script work/api-bom.gradle
```

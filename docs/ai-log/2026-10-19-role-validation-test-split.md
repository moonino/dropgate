# 잘못된 역할의 거부와 무효화 미조회를 분리하지 않는다

| 항목 | 내용 |
|---|---|
| 날짜, 도구 | 2026-10-19, Claude Code 자동 리뷰 지적(인라인) |
| 제안 요지 | 역할 오류의 401 단언과 Redis 무효화 조회 0회 단언은 두 개념이므로 별도 테스트로 나눈다. |
| 왜 틀렸나 | 과잉. 두 단언은 잘못된 역할의 토큰을 Redis 조회 전에 거부한다는 순서 계약 한 개념을 검증한다. 오류만 확인하면 먼저 Redis를 읽은 잘못된 구현을 놓치고, 조회 횟수만 확인하면 인증 자체가 거부됐는지 놓친다. AGENTS.md는 같은 개념의 여러 단언을 허용한다. 제안의 두 번째 테스트도 동일 입력에 같은 오류 단언과 조회 횟수 단언을 함께 남겨 중복만 생긴다. |
| 어떻게 알았나 | 문서와 코드 대조. 를 AGENTS.md의 테스트 규칙과 대조했다. verify는 역할을 읽은 뒤 마지막에 무효화를 확인하므로 두 단언이 같은 실행 순서를 고정한다. 기존 docs/ai-log/2026-10-17-drop-closed-test-split.md도 거부와 부작용 없음을 한 계약으로 판단한 사례다. [필수 지적과 제안 코드](https://github.com/moonino/dropgate/pull/132#discussion_r4310753806). |
| 대신 한 것 | 이름을 `잘못된 역할은 Redis 무효화 확인 전에 거부한다`로 명확히 하고 두 단언을 같은 테스트에 유지한다. PR #132. |

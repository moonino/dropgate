# 영구 실패 전환과 계측을 같은 테스트로 고정한다

| 항목 | 내용 |
|---|---|
| 날짜, 도구 | 2026-10-19, Claude Code 자동 리뷰 제안(요약 댓글의 제안) |
| 제안 요지 | 열 번째 실패의 FAILED 전환과 재선택 방지, 실패 카운터 1회 증가를 별도 테스트로 나눈다. |
| 왜 틀렸나 | 과잉. 열 번째 일반 실패를 영구 실패로 기록하고 한 번만 계측한다는 한 처리 계약이다. 테스트 이름도 FAILED 상태와 카운터 1회를 함께 밝힌다. 같은 잘못된 이벤트와 11회 실행을 다시 준비해 나누는 변경은 같은 시나리오를 중복하고 새로운 계약을 추가하지 않는다. 각 단언은 실패 위치와 실제 값으로 어느 결과가 달랐는지 보여준다. |
| 어떻게 알았나 | 테스트. [리뷰 제안](https://github.com/moonino/dropgate/pull/139#issuecomment-6260917694)을 AGENTS.md의 같은 개념 다중 단언 허용과 04 문서의 10회 영구 실패 및 계측에 대조했다. 실제 DB의 잘못된 이벤트가 attempts 10, FAILED, 카운터 증가 1로 남고 11번째 실행에 재선택되지 않는 것을 JDK 21의 `JAVA_TOOL_OPTIONS=-XX:ActiveProcessorCount=2 ./gradlew --max-workers=2 ktlintCheck :order-service:test`의 전체 order 189개에서 확인했다. |
| 대신 한 것 | 영구 실패 상태와 단 한 번의 계측을 같은 테스트에 유지한다. PR #139. |

# 완료 요약은 실행 판정을 통과한 뒤 출력한다

| 항목 | 내용 |
|---|---|
| 날짜, 도구 | 2026-10-19, Claude Code 자동 리뷰 제안(요약 댓글의 제안) |
| 제안 요지 | print_summary를 verify_reconciliation과 verify_k6_summary 앞으로 옮겨 판정 실패 때도 k6 요약을 바로 보게 한다. |
| 왜 틀렸나 | 과잉. 실패 진단을 편하게 하는 출력 순서 변경은 가능한 개선이지만 k6 원본 요약은 이미 파일에 보존되고 판정 실패 로그도 검사한 파일 경로를 안내한다. 화면의 가공 요약이 생략돼도 원본 정보가 사라지는 것은 아니다. 현재 흐름은 판정을 통과한 뒤 요약과 환경을 출력하고 완료 기록을 만드는 순서가 명확하므로 추가 실행 순서 변경은 미룬다. |
| 어떻게 알았나 | 문서 대조. [최신 리뷰 제안](https://github.com/moonino/dropgate/pull/160#issuecomment-6263291405)을 head 7df4582의 run_k6, verify_reconciliation, verify_k6_summary, main과 cleanup에 대조했다. run_k6는 호스트에 연결한 결과 디렉터리에 SUMMARY_FILE을 저장하며 cleanup은 그 파일을 삭제하지 않는다. 두 판정의 실패 메시지는 각 원본 경로를 표시하고 main은 두 판정 뒤에 print_summary를 호출한다. 해당 리뷰 검토 당시 실제 1만 요청 부하 실행은 0회였으며 이번 검토에서도 소스만 읽고 테스트나 부하를 실행하지 않았다. |
| 대신 한 것 | 원본 요약 보존과 실패 파일 안내를 유지하고 판정 뒤 요약을 출력하는 head 7df4582의 순서를 바꾸지 않는다. PR #160. |

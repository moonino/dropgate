# 0022 Redis 구매와 취소를 함께 활성화한다

- 상태: accepted
- 날짜: 2026-10-19
- 관련: ADR 0005, ADR 0007, ADR 0021, docs/design/02-Redis-키-설계.md 2절, 이슈 #113

## 맥락

독립 Lua 경계, DB 저장 실패 처리와 취소를 각각 300줄 이하 PR로 검증한다. 중간 PR에서 구매만 Redis로 바꾸면 DB 경로의 취소가 DB 재고만 되돌려 두 저장소가 어긋난다. 최종 redis 기본값 계약만으로는 이 중간 배포 상태의 설정을 설명하지 못한다.

## 결정

Redis 구매와 취소가 모두 준비될 때까지 중간 구현의 purchase-path 기본값은 db로 유지하고, 최종 활성화 PR에서 두 흐름과 기본값을 함께 redis로 전환한다.

- 중간 Lua 및 저장 경계 PR은 DB 구매와 취소 흐름을 계속 사용한다. Redis 초기화와 독립 Lua 테스트는 먼저 도입한다.
- 최종 전환 전 구매, 롤백 확인 보상, 커밋 불확실 예약 유지, DB 판매 상태 동기화와 DB 커밋 뒤 Redis 취소를 모두 실제 저장소로 검증한다.
- 최종 활성화 이후 redis가 기본이고 db는 같은 스위치로 구매와 취소를 함께 고르는 비교 기준선이다. ADR 0005대로 DB 경로는 Redis 재고를 변경하지 않는다.

## 대안

| 대안 | 장점 | 단점 | 안 고른 이유 |
|---|---|---|---|
| Lua 도입 즉시 구매만 전환 | 성공 구매를 먼저 사용할 수 있다 | 취소가 다른 재고를 복구한다 | 중간 배포에서 정합성이 깨진다 |
| 전체 구현을 한 PR에 합침 | 중간 설정이 없다 | 300줄 제한과 검토 가능한 변경 단위를 넘는다 | 저장소 규칙을 유지한다 |

## 결과

중간 PR의 기본값과 최종 계약을 구별해 기록한다. 활성화 PR은 설정 선언과 실제 구매, 취소 조립을 함께 바꾸며 두 모드의 계약 회귀를 통과해야 한다.

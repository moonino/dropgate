# 0004 배포 경로, kind 먼저 EKS 나중

- 상태: accepted
- 날짜: 2026-10-04
- 관련: docs/design/07-쿠버네티스-배포-설계.md, docs/plan.md 3절 6주와 7주와 5절 비용, 이슈 #11

## 맥락

Kubernetes 측정 질문은 넷이다. 부하 중 롤링 배포에서 오류가 나는가, 파드를 죽이면 몇 초에 회복하고 HPA는 몇 개까지 느는가, CronJob이 정시에 돌고 실패 시 재시도하는가, 그리고 운영 환경에서 노드 drain과 관리형 Redis 장애 조치는 어떤가. 앞의 셋은 로컬 클러스터로 답할 수 있고 마지막은 실제 클라우드가 있어야 한다. 비용은 7주 차 한 주 약 8.5만 원으로 추정했고, 1에서 6주는 0원이어야 한다.

## 결정

6주 차까지 kind에서 전부 돌리고 7주 차에만 EKS를 Terraform으로 만들어 실측한 뒤 내린다. Helm 차트는 하나이고 values 파일 둘(kind, eks)로 환경을 가른다.

- kind를 먼저 쓰는 이유는 비용과 반복 속도다. 6주 동안 매일 배포하고 파드를 죽이는 실험을 EKS에서 하면 비용이 열 배가 되고, 클러스터 생성에만 15분이 든다.
- EKS를 마지막에 하는 이유는 kind로 답할 수 없는 질문이 남아서다. 노드 drain, ElastiCache 자동 장애 조치, ALB, IRSA는 로컬에 없다. 그리고 "EKS에 올려 봤다"가 아니라 "같은 차트가 두 환경에서 돌고 수치가 이렇게 달랐다"가 기록으로 남는다.
- 차트를 하나로 두는 이유는 환경 차이를 values 두 파일의 diff로 읽을 수 있게 하기 위해서다. 차트가 둘이면 어느 차이가 환경 때문이고 어느 차이가 실수인지 가를 수 없다.
- Terraform으로 만드는 이유는 destroy가 한 명령이어야 비용이 멈추기 때문이다. 콘솔로 만들면 지우다 남긴 자원이 과금된다.

## 대안

| 대안 | 장점 | 단점 | 안 고른 이유 |
|---|---|---|---|
| 처음부터 EKS | 환경 차이로 되돌아갈 일이 없다 | 6주 비용이 약 50만 원. 실험 반복이 느리다 | 측정 대부분은 로컬로 충분하다 |
| docker compose만 | 가장 단순 | 롤링 배포, HPA, PDB, CronJob 실험이 불가능하다 | Kubernetes 측정 질문을 못 답한다 |
| minikube 또는 k3d | kind와 비슷 | kind가 멀티 노드 구성이 가장 단순하고 GitHub Actions에서도 그대로 돈다 | 차이가 작아 익숙한 쪽을 택했다 |
| 7주 차에 ECS | EKS보다 싸고 단순 | Deployment, HPA, PDB 같은 Kubernetes 자원이 없어 kind 결과와 비교가 안 된다 | ADR 0015에서 비교만 하고 택하지 않는다 |

## 결과

- kind와 EKS는 같은 차트지만 뒤가 다르다. Redis는 Bitnami Sentinel 차트 대 ElastiCache, PostgreSQL은 로컬 컨테이너 대 RDS, Ingress는 nginx 대 ALB. 두 환경의 수치를 비교할 때 이 차이를 함께 적는다.
- 7주 차 비용 약 8.5만 원은 추정이고, 실제 청구액을 측정 기록에 남긴다. 측정이 끝나면 terraform destroy를 바로 돌린다.
- 6주 차까지 EKS 전용 기능(IRSA, External Secrets Operator)은 코드에 없다. 7주 차에 처음 붙이므로 그 주가 가장 위험하다. 축소 순서 마지막이 "EKS를 빼고 kind 결과로 마무리"인 이유다.
- 측정으로 확인할 것: 같은 롤링 배포 10회와 파드 종료 실험을 kind와 EKS에서 돌렸을 때 5xx 수와 회복 초가 얼마나 다른가.

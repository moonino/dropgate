# 0020 웹 프론트는 같은 레포의 Next.js BFF로 둔다

- 상태: accepted
- 날짜: 2026-10-17
- 관련: docs/design/10-웹-프론트.md, docs/design/08-시퀀스-흐름.md 1절, docs/design/00-설계-개요.md 3절과 6절, ADR 0002, ADR 0003, 이슈 #90

## 맥락

지금까지 설계는 API만 정했고 화면이 없었다. 동작을 사람이 눌러 보고 보여 줄 수 있게 웹 화면을 두기로 했다. 정해야 할 것은 셋이다. 프론트를 어디에 두는가, 브라우저가 토큰을 어떻게 다루는가, 카카오 로그인 콜백이 지금처럼 auth-service에서 토큰 쌍 JSON으로 끝나는 흐름을 화면에 어떻게 잇는가다. 웹 프론트는 플랜 1절의 측정 대상 기술이 아니므로 범위를 키우지 않는 쪽으로 정한다.

## 결정

웹 프론트는 같은 레포의 `web/`에 Next.js(App Router, TypeScript) 앱으로 두고, 브라우저는 web 서버하고만 통신하며 web 서버가 auth-service와 order-service와 notification-service를 대신 부르는 BFF로 만든다.

- 같은 레포에 두면 openapi.yaml에서 API 타입을 바로 만들 수 있어 계약이 어긋나면 타입 검사가 깨진다. PR 규칙, CI, 이슈도 하나로 관리한다.
- 토큰은 web 서버가 httpOnly, Secure, SameSite=Lax 쿠키로 들고, 브라우저의 스크립트는 토큰을 읽지 못한다. 화면 코드가 토큰을 다루지 않으므로 XSS가 있어도 토큰이 새지 않는다.
- 브라우저 입장에서는 출처가 web 하나라 CORS 설정이 필요 없다. 이슈 #6 리뷰에서 나온 CORS 미설계 질문은 이 결정으로 닫는다.
- 카카오 Redirect URI를 web의 `/auth/callback/kakao`로 바꾼다. web은 로그인 시작과 콜백을 auth-service로 그대로 중계하고, 콜백에서 받은 토큰 쌍을 쿠키에 담은 뒤 드롭 목록으로 보낸다. auth-service의 state 쿠키(Path=/auth)는 web 출처에 그대로 실리므로 auth-service 코드는 바뀌지 않는다.
- 서비스 사이 동기 호출을 두지 않는다는 ADR 0002 경계 규칙은 그대로다. web은 데이터를 갖지 않는 클라이언트이고, 서비스끼리는 여전히 서로 부르지 않는다.
- Next.js 서버는 화면 렌더링과 중계만 한다. 비즈니스 규칙(재고, 1인 1회, 취소 가능 여부)은 백엔드가 정하고, web은 응답의 code로 문구와 버튼 상태만 고른다.

## 대안

| 대안 | 장점 | 단점 | 안 고른 이유 |
|---|---|---|---|
| 별도 레포 | 프론트와 백엔드 이력이 섞이지 않는다 | openapi.yaml 동기화가 수작업, CI와 이슈가 둘 | 혼자 하는 실험 프로젝트에서 관리 비용만 늘어난다 |
| 브라우저 SPA가 Bearer로 직접 호출 | 서버가 하나 줄어든다 | 토큰이 스크립트에 노출, CORS 설계가 필요, 카카오 콜백 JSON을 화면으로 받을 방법이 따로 필요 | 토큰 노출을 피할 이유가 더 크다 |
| 정적 데모 페이지 하나 | 가장 작다 | 화면이 늘면 구조가 없다 | 대기열과 알림 화면까지 이어 갈 계획이다 |
| springdoc Swagger UI만 | 비용이 거의 없다 | 사용자 흐름을 보여 주지 못한다 | 목적이 사용자 흐름 데모다. 계약 확인용으로는 따로 붙일 수 있다 |

## 결과

- 카카오 개발자 콘솔의 Redirect URI와 `DROPGATE_KAKAO_REDIRECT_URI`가 `http://localhost:3000/auth/callback/kakao`로 바뀐다. 이슈 #55와 #61의 확인 순서도 이 값으로 고친다.
- 6주 차 kind 배포에 web Deployment 하나가 늘고 Ingress의 `/`가 web을 가리킨다. 07 문서는 그때 고친다.
- 리프레시와 로그아웃(2주 차)이 생기면 web이 리프레시 쿠키로 재발급을 중계해야 한다. 그 흐름은 2주 차에 10 문서에 더한다.
- web 서버가 장애점이 하나 더 생긴다. 로그아웃 토큰 거절 시간 측정(플랜 2절 인증 행)은 web을 거치지 않고 서비스에 직접 요청해 잰다. web을 거치는 경로는 측정 대상이 아니다.
- 카카오 로그인 버튼만 카카오 로그인 디자인 가이드의 바탕색과 글자색을 쓴다. 게이트 보드 강조색으로 바꾸면 카카오 로그인임을 알아보기 어렵기 때문이다. 이 두 색도 hex를 화면 코드에 쓰지 않고 `--color-kakao-*` 토큰 둘로 두며(10 문서 7절), 다른 화면에는 쓰지 않는다. 모양은 다른 버튼과 같은 알약이다.

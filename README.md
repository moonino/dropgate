# dropgate

한정판 드롭 플랫폼. 기술 실험용 B2C 개인 프로젝트. Kotlin, Spring Boot 4, Kubernetes, Redis(Sentinel, Streams), DynamoDB, Spring Batch, 카카오 OAuth2와 JWT, Spring AI 운영 비서. 2026-10-06 착수, 7주 + 버퍼 1주 + 운영 비서 2주.

재고 100개에 요청 10000건, VU 500의 합성 부하다. 같은 Mac에서 대기열을 끄고 서비스 1개와 단일 Redis로 각 5회 측정했다. 각 시간은 실행별 p99의 중앙값(최소에서 최대)이며 전체 요청을 합친 p99가 아니다. 요청/초도 실행별 값 5개의 중앙값과 범위다.

| 경로 | 전체 p99(ms) | 201 p99(ms) | 전체 요청/초 | 초과 / 중복 / 모드 검사 차 |
|---|---|---|---|---|
| DB | 640.55 (597.88에서 666.56) | 545.54 (498.06에서 574.36) | 2427.55 (2212.45에서 2476.44) | 0 / 0 / 0 |
| Redis | 216.23 (171.39에서 230.02) | 2182.81 (2093.34에서 2358.53) | 4296.55 (4102.25에서 4555.64) | 0 / 0 / 0 |

Redis의 전체 지표와 성공 응답 지연은 다른 방향이었다. [환경, 명령과 실행별 결과](docs/measurements/2026-10-19-redis-stock.md)를 함께 본다. 측정 질문은 docs/plan.md 2절이다.

## 무엇을 하는가

사용자는 카카오로 로그인해 한정 수량 드롭의 접속 대기열에 들어가고, 입장되면 60초 안에 1인 1개를 구매한다. 주문은 PostgreSQL 불변 원장에 남고, 이벤트가 Redis Streams를 거쳐 DynamoDB 알림 피드에 쌓인다. 배치가 일별 결산과 Redis 대 DB 대조를 돈다. 결제는 없다.
